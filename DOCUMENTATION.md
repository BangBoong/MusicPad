# Повна документація архітектури та DSP ядра MusicPad

## 1. Загальний огляд системи

**MusicPad** — це спеціалізований Windows-застосунок (аналог Soundpad), призначений для цифрового відтворення локальних звукових файлів, швидкого пошуку і трансляції музики з YouTube Music, а також мікшування звуку з фізичного мікрофона в реальному часі з мінімальною затримкою (low-latency).

Отриманий змішаний сигнал транслюється у віртуальний аудіопристрій (VB-Audio Virtual Cable, `CABLE Input`), звідки інші програми (Discord, TeamSpeak, OBS, ігри: CS2, Dota 2 тощо) зчитують його як звичайний мікрофон користувача (`CABLE Output`). Одночасно програма забезпечує локальний моніторинг у навушниках без неприємного відлуння власного голосу.

## 2. Архітектура пайплайну цифрової обробки сигналів (DSP Engine)

Пайплайн спроєктовано за принципами системного програмування низькорівневого аудіо та цифрової обробки сигналів (DSP):

### 2.1. Вхідні потоки
1. **Вхід 1 (Фізичний мікрофон)**:
   - Аудіопотік з фізичного мікрофона користувача захоплюється звуковим бекендом з фіксованим блоком (blocksize = 384 семпли).
   - Вхідний сигнал нормалізується у формат IEEE 754 `float32` у діапазоні $[-1.0, 1.0]$.
   - Якщо мікрофон одноканальний (моно), сигнал автоматично дублюється на обидва стереоканали.
   - Сигнал масштабується коефіцієнтом `mic_volume` ($0.0 \dots 2.0$) або обнуляється, якщо активний режим `mic_muted`.

2. **Вхід 2 (Аудіотрек)**:
   - Джерелом треку може бути будь-який локальний файл (`.wav`, `.mp3`, `.ogg`, `.flac`, `.m4a` тощо) або стрім YouTube Music.
   - Відтворення керується тригерами: `play()`, `pause()`, `resume()`, `stop()`, `seek(seconds)`.

## 3. Технічні характеристики DSP та математичні алгоритми

### 3.1. Єдина частота дискретизації: 48 000 Гц
Система використовує єдину частоту дискретизації **48 000 Гц** (`SAMPLE_RATE = 48000`). Це сучасний стандарт для цифрового голосового зв'язку, ігрових рушіїв та відеоплатформ, що усуває постійні перетворення між частотами в операційній системі.

### 3.2. Векторний ресемплінг (Resampling)
Будь-який аудіотрек, частота дискретизації якого відрізняється від системних 48 кГц (наприклад, 44 100 Гц для CD-якості або 22 050 Гц для старих звукових ефектів), автоматично ресемплюється:
- При відтворенні через FFmpeg: автоматичний внутрішній високоякісний фільтр `libswresample` (`-ar 48000 -ac 2`).
- При читанні локальних файлів WAV або внутрішніх буферів: метод `AudioEngine.resample_to_48k_float32()` здійснює поліфазну інтерполяцію через векторизовані операції NumPy:
  $$N_{\text{target}} = \text{round}\left(N_{\text{source}} \cdot \frac{48000}{R_{\text{source}}}\right)$$
  $$x_{\text{target}}[n, c] = \text{interp}\left(t_{\text{target}}, t_{\text{source}}, x_{\text{source}}[:, c]\right)$$

### 3.3. Низька затримка (Low Latency) та розмір буфера
- За замовчуванням розмір буфера становить **384 семпли** (`blocksize = 384`).
- При частоті 48 000 Гц один буфер триває:
  $$\tau = \frac{384}{48000} = 0.008 \text{ с} = 8.0 \text{ мс}$$
- За потреби затримку можна налаштувати в межах **256–512 семплів** (від 5.33 мс до 10.67 мс), що забезпечує ультранизьку затримку передачі голосу без ризику виникнення артефактів спустошення буфера (buffer underrun).

### 3.4. Гібридний Soft-Knee лімітер та захист від кліпінгу
При одночасному звучанні гучної мови та музичного треку їхня сума може перевищувати максимальний амплітудний рівень $0 \text{ dBFS} = 1.0$. Звичайне жорстке обрізання (Hard Clipping) призводить до виникнення різких непарних гармонік та чутного хрипу/тріску.

У MusicPad реалізовано гібридний **Soft-Knee Limiter** (`apply_soft_knee_limiter`):
1. **Порогове значення (Threshold)**:
   $$T = 10^{-1.0 / 20.0} \approx 0.8912509 \quad (-1 \text{ dBFS})$$
2. **Лінійна зона ($|x| \le T$)**:
   $$f(x) = x$$
   Забезпечує абсолютну 100% бітову прозорість без фазових спотворень для звичайних рівнів звуку.
3. **Зона плавного насичення ($|x| > T$)**:
   Для надлишкового сигналу обчислюється коефіцієнт згладжування:
   $$e = \frac{|x| - T}{1.0 - T}$$
   $$f(x) = \operatorname{sgn}(x) \cdot \left[ T + (1.0 - T) \cdot \tanh(e) \right]$$
   Оскільки $\left.\frac{d}{de}\tanh(e)\right|_{e=0} = 1$, перша похідна в точці переходу $T$ є неперервною ($C^1$ гладкість), що повністю ліквідує клацання при спрацьовуванні лімітера.
4. **Кінцевий захисний Clamp**:
   $$y = \operatorname{clip}(f(x), -1.0, 1.0)$$
   Гарантує відсутність переповнення при перетворенні у 16-бітний цілочисельний потік.

## 4. Багатопотокова архітектура та Lock-Free буферизація

Операції читання файлів з диска, завантаження з мережі чи запуск процесів декодування категорично неприпустимі всередині аудіо-потоку реального часу, оскільки будь-яка затримка на блокуючих операціях призводить до тріску (audio glitch).

MusicPad розділяє виконання на 3 ізольовані потоки:

1. **GUI Thread (Головний потік Tkinter)**:
   - Відповідає за відображення віджетів, обробку подій вікна, системних меню та кліків.
   - Реєструє глобальні клавіші (F1–F12 тощо).
   - Надсилає високорівневі команди до аудіорушія (`play`, `seek`, `stop`, `set_volume`).

2. **Decoder Worker Thread (`musicpad-decode`)**:
   - Працює у фоні. Виконує запуск `ffmpeg.exe` або `_WavPipeDecoder`.
   - Зчитує пакети по 4096 байт, ресемплює їх до 48 000 Гц стерео `float32`.
   - Записує розкодовані дані у кільцевий буфер `Float32RingBuffer`.
   - Реалізує керування потоком (Flow Control): якщо кільцевий буфер заповнений, потік короткочасно призупиняється (`time.sleep(0.005)`).

3. **Real-Time Audio Thread (`musicpad-audio`)**:
   - Обслуговує регулярний аудіо-цикл затримкою 8.0 мс.
   - Виконує неблокуюче читання мікрофона.
   - Забирає з `Float32RingBuffer` рівно `blocksize` семплів без жодних системних викликів вводу-виводу (час взяття блоку становить $< 1 \text{ мкс}$).
   - Виконує векторизоване мікшування та лімітер (~18 мкс).
   - Записує готові семпли у вихідні аудіопотоки.

### Кільцевий буфер `Float32RingBuffer`
- Ємність: 65 536 фреймів (~1.36 секунди звуку при 48 кГц).
- Має роздільні покажчики запису та читання.
- Підтримує атомарний метод `reset()`: при натисканні Stop, Seek або перемиканні треку буфер очищується миттєво, усуваючи будь-яке накладання старого треку на новий.
- При спустошенні буфера (Underrun) читання автоматично доповнює відсутні семпли нулями (`0.0`), запобігаючи аварійним зупинкам аудіодрайвера.

## 5. Маршрутизація пристроїв та Налаштування

### 5.1. Меню та панель налаштувань
Вікно «Налаштування» (доступне через «Файл» -> «Налаштування» або гарячу клавішу) містить 4 основні вкладки:
1. **«Аудіо»**:
   - Нормалізація гучності (динамічне або фіксоване регулювання зі значенням за замовчуванням 89,0 дБ).
   - Блокування голосу під час відтворення звуку в мікрофон.
   - Налаштування звуку для голосової активації, затримка мікрофона та дакінг (автоприглушення).
2. **«Гарячі клавіші»**:
   - Таблиця спеціальних дій (зупинка, пауза, попередній/наступний трек, гучність, збереження, скасування тощо).
   - Автоматичне натискання клавіш («Push-to-Talk» / Auto-Keys) та модифікатори.
3. **«Інтерфейс»**:
   - Стиль інтерфейсу (Темний/Світлий), масштабування та колірна схема.
   - Частота оновлення шкали позиції треку (за замовчуванням 60 Гц).
   - Поведінка вікна (поверх усіх вікон, згортання в трей, пошук при введенні тексту).
4. **«Пристрої» (Оновлена 4-рольова конфігурація)**:
   - **[ComboBox 1] «Фізичний мікрофон»**:
     - *Фільтр*: Тільки пристрої захоплення (Capture / Input, `max_input_channels > 0`).
     - *Призначення*: Захоплення живого голосу користувача (наприклад, USB-мікрофон Fifine, гарнітура).
   - **[ComboBox 2] «Джерело треків / звуку»**:
     - *Значення за замовчуванням*: `«Вбудований аудіоплеєр (Локальні файли + YouTube Music)»`.
     - *Додаткові варіанти*: Можливість вибору зовнішніх вхідних аудіоканалів (Line In, Stereo Mix тощо).
   - **[ComboBox 3] «Навушники (лише трек)»**:
     - *Фільтр*: Тільки пристрої відтворення (Render / Output, `max_output_channels > 0`).
     - *Призначення*: Фізичний моніторинг для користувача. Сюди надсилається **ТІЛЬКИ звук треку** (голос мікрофона сюди НЕ потрапляє, щоб користувач не чув власного відлуння).
   - **[ComboBox 4] «Віртуальний кабель (мікс для Discord)»**:
     - *Фільтр*: Тільки пристрої відтворення (Render / Output, `max_output_channels > 0`).
     - *Призначення*: Пристрій `CABLE Input (VB-Audio Virtual Cable)`. Зворотний бік цього кабелю (`CABLE Output`) обирається як мікрофон у Discord, CS2, Dota 2, Zoom чи OBS.
   - **Кнопка «⟳ Оновити список»**:
     - Миттєво перескановує доступні аудіопристрої Windows та оновлює списки у всіх ComboBox без перезапуску програми.
   - **Збереження стану**:
     - Усі вибрані пристрої та джерела автоматично персистуються у файлі конфігурації `.cache/musicpad_state.json`.

### 5.2. Паралельна маршрутизація аудіопотоків (Dual Parallel Routing)
У процесі обробки аудіосигналу рушій формує два незалежних PCM-потоки з єдиною частотою 48 000 Гц:
1. **Потік 1: Моніторинг у навушниках (`monitor_stream`)**:
   $$\text{Headphones\_Out} = \text{Track\_Float} \times \text{Track\_Volume}$$
   Фізичний мікрофон повністю виключений з цього тракту, що гарантує комфортну гру та спілкування без ехо-ефекту.
2. **Потік 2: Віртуальний кабель (`stream` -> `CABLE Input`)**:
   $$\text{Mixed} = (\text{Mic\_Float} \times \text{Mic\_Volume}) + (\text{Track\_Float} \times \text{Track\_Volume})$$
   $$\text{Cable\_Out} = \text{Limiter}(\text{Mixed})$$
   Сигнал проходить через гібридний Soft-Knee Limiter з порогом $-1 \text{ dBFS}$ і захисним обмеженням у діапазоні $[-1.0, 1.0]$, унеможливлюючи появу цифрового кліпінгу.

## 7. Централізована система сповіщень та кастомна спливаюча хмарка (Speech Bubble Popup)

У додатку реалізовано сучасну централізовану систему сповіщень замість застарілого статичного текстового лейбла у нижній панелі.

### 7.1. Архітектура NotificationManager
- **Клас `NotificationManager`**:
  - `notify(message, category="info")`: публікація сповіщення з підтримкою категорій `"info"` (інформаційні події, збереження списку, перемикання налаштувань) та `"error"` (помилки аудіопотоку, мережі, кешування).
  - `notify_info(message)` та `notify_error(message)`: спеціалізовані методи швидкої відправки.
  - `toggle_bubble()`: перемикання відкриття/закриття хмарки при натисканні на кнопку 💬 у правому нижньому куті.
  - `show_last()`: повторне відображення останнього повідомлення.
- **Потокобезпечність (Thread-Safety)**:
  - Будь-який виклик з фонових потоків (FFmpeg, worker-потоки AudioEngine, yt-dlp тощо) автоматично детектується та безпечно передається у головний UI-потік через чергу `_safe_ui_call` або `root.after`.
  - Безпечна маршрутизація викликів `.set(...)` навіть якщо вони викликаються з вторинного потоку.
- **Придушення фантомних сповіщень**:
  - Коли програма згорнута (`iconic`) або схована у системний трей (`withdrawn`), спливаюча хмарка не показується у порожньому просторі робочого столу; натомість оновлюється статус останнього повідомлення та за наявності надсилається системне сповіщення трею.
- **Повна зворотна сумісність**:
  - `NotificationStringVar` — спеціальна обгортка над `tk.StringVar`, яка перехоплює виклики `.set(...)` та автоматично перенаправляє їх до `NotificationManager`, зберігаючи доступність викликів `.get()` для юніт-тестів та існуючої кодової бази.

### 7.2. Кастомний віджет SpeechBubble
- **Форма хмарки діалогу**:
  - Векторна побудова на `tk.Canvas` з округленими кутами (радіус 10 px) та кутовим хвостиком знизу, спрямованим безпосередньо на іконку повідомлень (💬) у правому нижньому куті.
  - Використання кольорового ключа прозорості (`-transparentcolor`) для бездоганного відображення без синіх або сторонніх прямокутних рамок з коректним фолбеком для середовищ без підтримки апаратного DWM.
  - Повна підтримка конфігурацій з кількома моніторами (Multi-Monitor): віджет коректно відображається над кнопкою на моніторах з від'ємними та додатними координатами без примусового стягування на первинний дисплей.
- **Дві теми інтерфейсу**:
  - **Темна тема** (`tb_style="Темний"`, `theme="dark"`): фон `#232323`, акуратна рамка `#3d3d3d`, білий текст, акцентна іконка `ℹ` (`#38bdf8`) для info та `✕` (`#ff4d4f`) для error.
  - **Світла тема** (`tb_style="Світлий"`, `theme="light"`): білий фон `#ffffff`, сіра рамка `#cccccc`, темний текст `#1a1a1a`, акцентна іконка `ℹ` (`#0078d4`) для info та `✕` (`#d93025`) для error.
  - Динамічна зміна теми хмарки на льоту при перемиканні теми в меню, вікні налаштувань чи через гарячу кнопку.
- **Поведінка та анімації**:
  - Плавна поява через alpha-анімацію з початковим рівнем 0.0 без мерехтіння чи спалахів при першому відображенні.
  - Автоматичне закриття через 4 секунди.
  - Миттєве закриття при кліку на будь-яку точку хмарки або кнопку `×` (з підсвічуванням при наведенні курсору).
  - Підтримка швидкої черги сповіщень: при надходженні нових повідомлень текст та іконка оновлюються на льоту без втрати прозорості та без перезапуску анімацій, а 4-секундний таймер скидається.
- **Керування та доступність**:
  - Кнопка 💬 у правому нижньому куті дозволяє в будь-який момент відкрити останнє отримане повідомлення або миттєво закрити поточне.
  - Панель пошуку YouTube Music залишається доступною через ліву панель категорій («YouTube»), контекстні меню та глобальну комбінацію `Ctrl+Shift+Y`.

## 8. Повна динамічна система тем (Light/Dark Theme), прокручуване вікно налаштувань та векторна графіка

Усі елементи — заголовок панелі (`yt_titlebar`), іконка, назва, кнопка закриття (✕), поле пошуку з рамкою, статусний напис, рамка результатів, нижній блок дій та кнопки («Відтворити», «Закешувати», «Закрити») — динамічно оновлюються в `_apply_theme()` відповідно до палітри теми.

  - **Кастомні слайдери (`SoundpadTimelineSlider` та `SoundpadVolumeSlider`)**: оснащені методом `set_theme(theme)` для динамічного перемальовування жолобків (`#141414` проти `#d0d4da`) та бігунка (`#0084d1` проти `#007acc`).

  - **Час ініціалізації теми**: виклик `_apply_theme()` виконується наприкінці створення інтерфейсу (`_build_ui()`), що забезпечує автоматичне та повне застосування правил до всіх створених віджетів одразу при старті програми.
- **Підтримка темного заголовка вікна (Windows DWM)**: функція `_apply_dark_title_bar` з викликом `DwmSetWindowAttribute` (атрибути 20 та 19 для сумісності з усіма версіями Windows 10/11) автоматично застосовується як до головного вікна, так і до вікна налаштувань (до та після деіконіфікації) та вторинних діалогів.

## 9. Відображення та поведінка випадних меню верхньої панелі (Menu Bar)

У додатку реалізовано професійне графічне оформлення та класичну ергономіку верхнього рядка меню (Menu Bar), характерну для стандартних Windows-програм та сучасних IDE (Visual Studio, VS Code, Soundpad).

### 9.1. Стилізація рамок випадних меню та нативна темна тема (Windows DWM & Tkinter)
- **Усунення товстої білої рамки**:
  - У класичних випадних вікнах меню (QMenu / Tk Menu) за замовчуванням у Windows відображалася занадто товста біла обводка та рельєфні 3D-фаски, що створювало різкий дискомфортний контраст із темним фоном програми.
  - Параметри конфігурації меню приведені до сучасного мінімалістичного стандарту: `relief="solid"`, товщина рамки `bd=1` (1 px) та нульова внутрішня активна межа `activeborderwidth=0`.
- **Централізовані кольори рамок у палітрі `_get_theme_colors()`**:
  - У темній темі: тонка акуратна рамка `menu_border="#3f3f3f"` на темному фоні `menu_bg="#1a1a1a"` з виділенням пунктів `active_menu_bg="#333333"`.
  - У світлій темі: чистий нейтральний контур `menu_border="#d0d4da"` на світлому фоні `menu_bg="#eaedf1"` з виділенням пунктів `active_menu_bg="#d0d4da"`.
  - Метод рекурсивного оновлення `_update_menu_recursively(menu)` автоматично транслює дані параметри на всі рівні вкладеності (головне меню, каскади підменю «Експорт», «Статистика», «Вибрати останній файл», а також контекстні меню списку треків `_track_menu` та категорій `_cat_menu`).
- **Глибока нативна інтеграція з Windows DWM та uxtheme**:
  - Виклик `uxtheme.SetPreferredAppMode` (ординал 135) з режимом `2` (ForceDark) для темної теми та `3` (ForceLight) для світлої теми повідомляє менеджер вікон Windows про колірну модель застосунку.
  - Автоматичне перехоплення подій запуску спливаючих вікон через глобальний хук `SetWinEventHook` з ідентифікатором `EVENT_SYSTEM_MENUPOPUPSTART` (0x0006) для поточного потоку.
  - Повна 64-бітна типізація викликів Win32 ctypes (`argtypes` та `restype` для `SetWinEventHook`, `UnhookWinEvent`, `AllowDarkModeForWindow`, `DwmSetWindowAttribute`), що унеможливлює зрізання дескрипторів до 32 біт або помилки `ArgumentError: OverflowError` на сучасних версіях Windows.
  - При створенні системного вікна меню класу `#32768`:
    - Викликається `AllowDarkModeForWindow` (uxtheme ординал 133).
    - Застосовується атрибут `DwmSetWindowAttribute` з ідентифікаторами `DWMWA_USE_IMMERSIVE_DARK_MODE` (20, з фолбеком на 19).
    - На Windows 11 (Build 22000+) встановлюється точний колір системної межі через `DWMWA_BORDER_COLOR` (34): `0x003F3F3F` для темного режиму та `0x00DAD4D0` для світлого режиму.
  - Надійне відключення хука через `UnhookWinEvent` у методі `_teardown_windows_hooks()` під час завершення роботи програми (`_exit`).

### 9.2. Автоматичне перемикання сусідніх меню при наведенні курсора (Hover Switching State Machine)
- **Класична ергономіка Menu Bar**:
  - Усунуто дефект, коли за вже відкритого меню («Файл») наведення курсора на сусідні кнопки («Редагування», «Відтворення», «Вікно») лише змінювало форму курсора, вимагаючи додаткового клацання мишею для показу потрібного підменю.
  - Реалізовано стандартний механізм Menu Bar: щойно будь-яке меню активовано користувачем, простий рух курсора на будь-яку сусідню кнопку верхньої панелі миттєво згортає попереднє та розгортає нове підменю без потреби у повторних кліках.
- **Машина станів меню**:
  - `_is_menu_open: bool` — загальний прапорець активності режиму випадних меню.
  - `_active_menu_btn: Optional[tk.Menubutton]` — посилання на поточну підсвічену кнопку верхньої панелі.
  - `_active_menu: Optional[tk.Menu]` — посилання на відкритий віджет меню.
  - `_next_menu_btn: Optional[tk.Menubutton]` — цільова кнопка для перемикання при виявленні наведення курсора.
  - Публічний метод `is_menu_active() -> bool` надає зовнішнім компонентам і тестам статус активності меню.
- **Асинхронний неблокуючий трекер курсора (`_start_menu_hover_tracker`)**:
  - Оскільки метод `tk_popup` на платформі Windows викликає нативну функцію `TrackPopupMenuEx` і блокує виконання головного потоку Tkinter у внутрішньому циклі обробки повідомлень, обробники подій Tkinter не можуть своєчасно отримати події руху миші через захоплення вводу системним меню.
  - Для вирішення цієї проблеми створено фоновий потік-монітор (`_tracker`), який з інтервалом 15 мс запитує глобальні координати миші через `GetCursorPos()`.
  - Життєвий цикл трекера повністю ізольований: перед запуском нового трекера старий потік коректно зупиняється та очікується через `join(timeout=0.05)`, а кожна ітерація отримує власний унікальний `threading.Event()`, що повністю виключає витоки потоків при швидкому переміщенні курсора між меню.
  - Головний потік перед відкриттям кожного меню оновлює кеш екранних прямокутників кнопок (`_cache_menu_button_rects()`: `winfo_rootx`, `winfo_rooty`, `winfo_width`, `winfo_height`). Зона детекції кнопок охоплює повну висоту панелі меню `menu_frame` (`fill="y"`), усуваючи будь-які сліпі зони по вертикалі.
  - При попаданні курсора у межі сусідньої кнопки меню (`bx <= pt.x < bx + bw` та `by <= pt.y < by + bh`), трекер фіксує `_next_menu_btn` та надсилає повідомлення `WM_KEYDOWN` з кодом `VK_ESCAPE` (0x1B) цільовим вікнам класу `#32768` поточного процесу.
- **Надійне закриття меню без блокувань (`_close_current_popup`)**:
  - Замість одиночного `FindWindowW`, який блокується при наявності меню в інших сторонніх програмах, використовується ітеративний пошук `FindWindowExW`, що знаходить усі вікна `#32768`, які належать виключно нашому процесу (`PID`).
  - Коректно закриваються каскади багаторівневих підменю (наприклад, підменю експорту чи статистики).
  - Метод `active_m.unpost()` викликається лише на головному потоці, що усуває збої `RuntimeError: main thread is not in main loop` у Python 3.15.
- **Стійкість та зона дії (Work Area Isolation)**:
  - Якщо користувач переміщує курсор вниз за межі верхньої панелі меню (у таблицю треків, інфо-панель або панель категорій), відкрите меню залишається розгорнутим і не закривається спонтанно. Меню згортається лише при явному кліку поза межами меню, виборі команди або натисканні Escape.
  - Повторний рух курсора над тією ж самою активною кнопкою не призводить до мерехтіння чи зайвого перезапуску вікна.
- **Повна підтримка клавіатури та жестів**:
  - Підтримка відкриття за допомогою клавіш `Enter` та `Space`.
  - Дебаунс-захист від випадкового повторного відкриття того ж меню при кліку на його кнопку для закриття (інтервал 0.25 с).
