# ADR 0020: Залишаємося на Python; швидкодія запуску вирішується пакуванням і відкладеною ініціалізацією, а не переписуванням на Rust

## Context

Розглядалася ідея переписати MusicPad з Python на Rust. Реальні проблеми, які мали б вирішитися: **повільний запуск** програми та (меншою мірою) **підвисання інтерфейсу**.

Аналіз кодової бази показав:

1. **Гарячий шлях реального часу вже нативний.** Ін'єкція в мікрофон виконується драйвером MusicPad (`musicpad_apo.dll`, C++), обробка голосу — нативним DSP-ядром (`musicpad_dsp.dll`, C++), шумозаглушення DeepFilterNet — скомпільованою бібліотекою `deepfilter.dll` (сам DeepFilterNet написаний на Rust). Python лише оркеструє ці компоненти через `ctypes` та буфер ін'єкції у спільній пам'яті ([ADR-0001](./0001-injection-via-own-efx-apo.md), [ADR-0003](./0003-decoupled-injection-buffering.md), [ADR-0005](./0005-microphone-dsp-pipeline.md)). Переписування не дає виграшу в затримці звуку.
2. **Ключові можливості пошуку залежать від Python-only бібліотек.** `yt-dlp` та `ytmusicapi` не мають зрілих аналогів на Rust. Rust-версії довелося б постачати `yt-dlp.exe` окремим процесом і заново реалізовувати (або обходити) `ytmusicapi` — пошук, альбоми, пошукові підказки.
3. **Повільний запуск спричинений пакуванням та порядком імпортів, а не мовою:**
   - Релізний `MusicPad.exe` — це PyInstaller **onefile** розміром ~259 МБ зі стисненням **UPX**. При кожному запуску завантажувач розпаковує весь вміст (рантайм Python, numpy, FFmpeg/FFprobe, `deepfilter.dll`, модель DeepFilterNet) у тимчасову теку, попередньо розтискаючи UPX, а антивірус сканує щойно розпаковані DLL.
   - Важкі модулі (`yt_dlp`, `ytmusicapi`, `numpy`, `sounddevice`, `PIL`, `pystray`) імпортуються жадібно на рівні модулів ще до появи вікна.
   - Rust-версія все одно мусила б постачати FFmpeg, `yt-dlp` та модель DeepFilterNet, тобто зберегла б більшу частину розміру.
4. Кодова база — ~16.7 тис. рядків Python з одним тестовим модулем; повне переписування означало б багатомісячне замороження функціональності для реальних користувачів без надійної регресійної сітки.

## Decision

1. **Переписування на Rust не виконується.** MusicPad залишається Python-застосунком; нативні компоненти гарячого шляху (драйвер MusicPad, DSP-ядро, DeepFilterNet) залишаються в C++/нативних бібліотеках.
2. **Швидкодія запуску вирішується без зміни мови:**
   - Перед будь-якими змінами фіксується базова лінія: час до появи вікна (зібраний бінарник та `python main.py`) і розбивка `python -X importtime`. Ціль — вікно з'являється за **≤ ~2 с при теплому запуску** на машині розробника (число уточнюється після вимірювання базової лінії).
   - Релізний пайплайн переходить з PyInstaller **onefile** на **onedir**: публікується лише портативний ZIP із текою `MusicPad/` (`MusicPad.exe` + `_internal/`), без окремого onefile-`.exe`. Стиснення UPX вимикається.
   - `MusicPad.exe` виявляє запуск без розпакування архіву (відсутній `_internal/` поруч або запуск із тимчасової теки ZIP-провідника Windows) і показує зрозуміле повідомлення «Спочатку розпакуйте ZIP» замість падіння.
   - Важкі модулі (`yt_dlp`, `ytmusicapi`, `PIL`) імпортуються ліниво/у фоновому потоці після появи вікна. Пошук, розпочатий до завершення прогріву, показує стан «Завантаження…» і виконується автоматично.
   - Ініціалізація аудіо (відкриття пристроїв, перевірка стану драйвера) виконується одразу після появи вікна з бюджетом **≤ ~1 с**; натискання відтворення або гарячі клавіші до готовності ставляться в чергу й виконуються після готовності. Модель шумозаглушення DeepFilterNet завантажується лише коли шумозаглушення увімкнене.
3. **Портативність зберігається.** Користувацькі дані залишаються в `.cache/` поруч із `MusicPad.exe` (тека створюється автоматично при першому збереженні). Оновлення — розпакування нового ZIP поверх наявної теки `MusicPad/`; README вказує розпаковувати в теку з правом запису (не `Program Files`).
4. Підвисання інтерфейсу розглядається окремою задачею і не є аргументом на користь зміни мови.

Частково замінює [ADR-0009](./0009-headless-safe-ci-release-pipeline-and-deadlock-prevention.md) у частині формату артефакту: замість onefile `MusicPad.exe` + ZIP з ним публікується лише ZIP onedir-збірки; самотест виконується для `MusicPad/MusicPad.exe` з onedir-теки. Решта рішень ADR-0009 (таймаут джоби, тригери, відсутність GUI-тестів у релізі) залишається чинною.

## Consequences

- Найдорожчі складові запуску (розпакування onefile, розтискання UPX, сканування антивірусом тимчасових DLL, жадібні імпорти) усуваються без багатомісячного переписування й без втрати функціональності YouTube / YouTube Music.
- Користувач завантажує ZIP і запускає `MusicPad.exe` з розпакованої теки замість одного файлу; це документується в обох README.
- З'являється стан «програма видима, але аудіо/пошук ще прогріваються», який має бути коректно оброблений в інтерфейсі (черга дій, стан «Завантаження…»).
- Питання переписування на Rust слід переглядати лише за появи нових фактів, наприклад якщо після описаних оптимізацій запуск або інтерфейс залишаються неприйнятно повільними з причин, які неможливо усунути в Python.
