# 05: Фоновий прогрів модулів пошуку YouTube зі станом «Завантаження…»

**What to build:** `yt_dlp`, `ytmusicapi` і `PIL` більше не імпортуються до появи вікна, `pystray` — до першого використання трею. Після першого показу вікна аудіорушій запускає фоновий прогрів модулів пошуку й виставляє стан готовності. Пошук, пошукові підказки, альбоми, обкладинки треків і пряме відтворення за посиланням спершу чекають готовності у фоновому робочому потоці (не в UI-потоці). Якщо користувач запускає пошук до готовності, панель пошуку показує «Завантаження…» / «Loading…», а запит виконується автоматично; пошукові підказки для поточного тексту поля з'являються після готовності. Самотест доводить, що важкі модулі не завантажені до показу вікна. Див. [spec](../spec.md).

**Blocked by:** 01: Базова лінія часу запуску та скрипт вимірювання

**Status:** resolved

- [x] `yt_dlp`, `ytmusicapi`, `PIL` відсутні в `sys.modules` на момент першого показу вікна; `pystray` імпортується при першому використанні трею (поведінка трею не регресує).
- [x] Явна точка прогріву в аудіорушії: запуск у daemon-потоці після першого показу вікна (спільний хук «після показу вікна», який перевикористає задача 07), стан готовності, помилка прогріву зберігається й показується як звичайна помилка пошуку.
- [x] Тести можуть керувати моментом завершення прогріву (детермінована підміна), без залежності від таймінгів.
- [x] Пошук до готовності: локалізований стан «Завантаження…» / «Loading…» у панелі пошуку, потім автоматичне виконання й результати; введений запит не губиться.
- [x] Пряме відтворення за посиланням до готовності спрацьовує після прогріву.
- [x] Пошукові підказки до готовності не запитуються; після готовності — запитуються для поточного тексту поля.
- [x] Обкладинки треків (у пошуку, списку звуків, смузі керування треком) відображаються коректно після лінивого імпорту `PIL`, у темній і світлій темах.
- [x] Самотест звітує `window_shown_ms` (від старту Python-процесу) і `heavy_modules_loaded_before_window`; `has_yt_dlp` / `has_ytmusic` — після явного очікування прогріву; `ok` вимагає `heavy_modules_loaded_before_window == false`.
- [x] In-process GUI-тести: пошук до прогріву → «Завантаження…» → результати; підказки після прогріву; помилка прогріву.
- [x] Повторне вимірювання скриптом із задачі 01 записано під `## Comments`.
