# 08: Дослідити підвисання інтерфейсу

**What to build:** Окреме дослідження спостережуваних підвисань інтерфейсу MusicPad (низький пріоритет; не блокує й не блокується задачами 01–07). Імовірна причина — робота в головному потоці Tkinter (обробники подій, перемальовування канв списку звуків і результатів пошуку, синхронні I/O чи мережеві виклики). Спершу відтворити й виміряти, потім запропонувати виправлення окремою специфікацією. Контекст: [spec](../spec.md), [ADR-0020](../../../docs/adr/0020-stay-on-python-native-hot-path.md) — підвисання не є аргументом на користь зміни мови.

**Blocked by:** None (can start immediately)

**Status:** needs-triage

- [ ] Зібрано конкретні сценарії, в яких інтерфейс підвисає (дії користувача, розмір списку звуків, режим маршрутизації).
- [ ] Для кожного сценарію виміряно тривалість блокування головного потоку Tkinter і визначено відповідальний код.
- [ ] Результати та пропозиції виправлень записано під `## Comments`; за потреби — створено окрему специфікацію в `.scratch/`.
