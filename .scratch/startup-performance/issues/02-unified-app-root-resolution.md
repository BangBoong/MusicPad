# 02: Префакторинг — єдине правило кореня застосунку з підтримкою `dist/<тека>/`

**What to build:** Правило визначення кореня застосунку (де лежить `.cache/` з налаштуваннями, кешем YouTube, обкладинками, записами й TTS) зараз продубльоване в головному модулі та аудіорушії. Звести його в одну спільну функцію, якою користуються обидва місця, і розширити: якщо exe лежить у `dist/<тека>/`, а поруч із `dist` є `MusicPad.spec` — коренем вважається корінь репозиторію. Наявні правила (exe безпосередньо в `dist/` → корінь репозиторію; релізна тека → тека з exe; запуск із джерел → корінь репозиторію) зберігаються. Поведінка поточних збірок не змінюється. Готує ґрунт для onedir-збірки (задача 03). Див. [spec](../spec.md).

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] Існує одна функція визначення кореня застосунку; обидва попередні місця делегують їй (дублювання усунуто).
- [x] exe у `dist/` → корінь репозиторію (як раніше).
- [x] exe у `dist/<тека>/` поруч із `MusicPad.spec` → корінь репозиторію.
- [x] exe у `dist/<тека>/` без `MusicPad.spec` поруч із `dist` → тека з exe (релізний користувач, що випадково розпакував у теку `dist`).
- [x] Релізна тека (будь-яка інша) → тека з exe; запуск із джерел → корінь репозиторію.
- [x] Тести покривають усі випадки через підміну `sys.frozen` / `sys.executable` (за зразком наявного тесту frozen-шляхів кешу); наявний тест frozen-шляхів проходить без змін.
